## 🤝 介绍

批量权限管理插件，提供便捷的批量权限设置功能。已完全适配 AstrBot v4.24+ 原生 Page 页面系统，无需独立开启 Web 端口，直接集成在 AstrBot 管理面板中。

**主要特性：**
- ✅ **原生集成**：接入 AstrBot v4.24 Page 系统，直接在管理后台操作
- ✅ **批量操作**：一键批量设置整个插件的所有命令权限
- ✅ **可视化界面**：支持修改指令名、添加/删除别名、切换权限状态
- ✅ **完全兼容**：与原有的 `/alter_cmd` 配置完全同步
- ✅ **实时生效**：设置后立即生效，无需重启
- ✅ **三级权限**：区分框架管理员、群主/群管理员和所有人
- ✅ **私聊策略**：可在 Page 中为每条指令独立设置私聊可用性，权限不足提示默认静默
- ✅ **全局指令冷却**：同一群组内的所有指令共用冷却，可选择静默忽略或排队
- ✅ **Page 稳定展示**：插件 Logo 可在列表、搜索和详情页重复显示，支持包含空格的插件名

## 📦 安装

直接在 AstrBot 的插件市场中搜索 `astrbot_plugin_permission_manager` 安装或更新即可。

## 🐔 使用说明

### 1. 网页后台管理 (推荐)

1. 进入 AstrBot 管理后台。
2. 点击“插件”页面，找到“指令编辑拓展”插件。
3. 点击插件卡片进入详情页，点击“权限管理”原生页面。
4. 在这里可以：
   - 搜索并查看所有插件及其命令。
   - 批量或单独设置命令权限。
   - 直接修改指令名称和别名。

权限分为三级：

- `仅框架管理员`：只有 AstrBot 全局配置 `admins_id` 中的管理员可以使用。
- `群主/群管理员及框架管理员`：群聊中的群主、群管理员，以及 AstrBot 框架管理员可以使用；私聊中只有框架管理员满足该权限。
- `所有人`：任何用户均可使用，但私聊中仍受该指令的“私聊可用”开关限制。

群主/群管理员身份优先读取适配器提供的原始消息角色，其次尝试调用适配器的群信息接口；适配器未提供可验证的角色信息时会安全拒绝，不会把未知身份当作管理员放行。

私聊可用性在 Page 的每条指令行单独设置，关闭后仅拦截该指令的私聊调用。命令组可以在组行设置私聊开关，子命令默认继承最近的父组设置；子命令存在显式设置时，以子命令设置为准。

旧配置会自动兼容：旧 `admin` 映射为“仅框架管理员”；旧 `member` 与 `everyone` 过去运行效果相同，升级后都映射为“所有人”，不会意外收紧已有指令权限。

### 2. 命令行使用

- `/perm list`: 列出所有已启用的插件及其命令数量。

### 3. 全局指令冷却

在插件配置中设置以下选项即可启用冷却：

- `global_command_cooldown_seconds`：冷却间隔，单位为秒。默认 `0`（关闭）。同一平台的同一群组内，所有插件和所有指令共用一个冷却计时器；不同群组互不影响。私聊按平台和发送者独立计算。
- `cooldown_hit_mode`：命中冷却时的处理方式。`ignore` 会静默丢弃本次指令，`queue` 会静默等待可用时间后执行。

冷却从指令被接受时开始计算，排队模式按设定间隔依次放行，不会发送“冷却中”等提示。

### 4. 私聊与权限不足提示

每条指令的“私聊可用”开关在 Page 内单独设置，默认开启；命令组和子命令遵循上文所述的继承规则。

插件配置页提供两组提示开关与文案：

- `private_chat_notify` / `private_chat_denied_message`：指令关闭私聊后，是否发送以及发送什么提示。
- `group_admin_notify` / `group_admin_denied_message`：普通群成员触发群主/群管理员权限指令时，是否发送以及发送什么提示。

两组提示开关默认关闭，关闭时都会静默拦截。私聊被拦截或权限不足时，指令不会继续进入默认 LLM。

## 💡 使用场景

- **限制敏感指令**：一键将插件指令设为仅框架管理员，或仅群主/群管理员可用。
- **自定义指令名**：觉得默认指令太长？在界面里直接改成自己喜欢的。
- **添加快捷别名**：为常用指令添加简短别名。
